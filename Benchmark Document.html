Benchmark Report

Overview

This project benchmarks the performance of multiple JSON processing solutions under different workloads and dataset sizes. The primary goal is to compare execution speed across different implementations.

The benchmark focuses on common JSON processing operations such as filtering, mapping, and length calculation on generated datasets of varying sizes and nesting depths.

Note: Benchmark results are not representative at this time.

Motivation Behind Software Selection

The selected software solutions represent different approaches to JSON processing:
  • The custom Java implementations allow direct comparison between single-threaded and multi-threaded processing strategies.
  • The Python implementation provides insight into the performance characteristics of an interpreted language compared to Java.
  • jq serves as an established and highly optimized baseline commonly used for command-line JSON processing tasks.

Benchmark Environment

The selected software solutions represent different approaches to JSON processing:
  • The Java implementations are benchmarked using JMH
  • The Python implementation is benchmarked using pyperf
  • jq is benchmarked using Hyperfine

Conclusions

Since the results are not representative, it would be unfair to draw any concrete conclusions, however we can still compare how each implementation's runtime changed based on the dataset and the operations, which it had to do.

Looking at the filter operations, surprisingly the single-threaded implementation proved to be the faster one.

The non-nested map operations show that the multi-threaded Java implementations are noticably faster. With nested structures this difference reduces, but single-threaded is still consistently slower.

On the large (10M record) datasets we can see an expected speed difference between the single- and multi-threaded implementations in the non-nested filter_id, and map operations. Nested structures were much closer in runtime.

Overall the 3 level nested structure seems to slow down the runtime by roughly 2 times, though this is not consistent throughout the measurements.
